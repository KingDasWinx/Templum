# The Templum API, Batch 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution, already chosen:** a Sonnet 5.5 (high) implementer in a Templum block in the `card-171` worktree, then
> an Opus 5.5 (xhigh) reviewer, in a loop until the reviewer passes it. The implementer **commits nothing**:
> everything stays uncommitted for the orchestrator.

**Goal:** Kanban card 171, batch 1: an HTTP API inside Templum, off by default, that answers only to tokens the person
makes (read, control, full; an expiry; optional workspaces), serves every control tool as `POST /v1/tools/{name}`,
REST resources and aliases on the same registry, a generated OpenAPI document and a live event stream, over plain HTTP
on loopback or HTTPS anywhere, with Settings ▸ API and a title-bar pill.

**Architecture:** A new UI-free crate, `crates/templum-api`, holds the server (hyper 1 on a single-threaded tokio
runtime on its own thread), the tokens and their file, TLS (rustls with ring; rcgen makes Templum's certificate), the
registry (the control server's tools, the API's own, their scopes, the route table, the OpenAPI document), the
state's types and their comparison, the event hub and the audit log. The server hands each call to the UI thread as a
bus `Message` (`client: "api"`, the token's id as its `terminal`) through the bus's own channel, which
`workspace/bus.rs` already drains, and waits for its line on tokio's blocking pool. `crates/templum` holds the glue:
`workspace/api.rs` serves those messages (the scope and workspace checks, then the control server's dispatch with an
`Actor`), `workspace/api_state.rs` builds the state, `settings/api.rs` and the title bar show it.

**Tech Stack:** Rust 2024; hyper 1 (`server`, `http1`), hyper-util (`tokio`), http-body-util, bytes, tokio (`rt`,
`net`, `time`, `sync`, `io-util`), tokio-rustls (ring), ring, base64, form_urlencoded, futures, serde, serde_json; new:
rcgen 0.14 (`crypto`, `pem`, `ring`); tests: ureq 3, tempfile; GPUI through gpui-kit 0.7.3 (pinned) for the glue.

**Spec:** [docs/specs/api.md](../specs/api.md). Read it whole, then:
`crates/templum-mcp/src/{bus,control,tools,ask}.rs`,
`crates/templum/src/workspace/{bus,control,approvals,waits,questions,inbox,agents_view,automations,ops}.rs`,
`crates/templum/src/workspace/delegate.rs` (`push_notice`), `crates/templum/src/workspace/spawn.rs` (`Opener`),
`crates/templum/src/settings/{mod,sections,instructions,connections}.rs`, `crates/templum/src/title_bar.rs`, and the
tests' helpers in `crates/templum/src/workspace/tests/{mod,templum_agent,bus,requests,automations}.rs`
(`control_as` is the pattern for the API's test helper).

## Review Focus

1. **A token revoked while it is in use:** its open event stream ends at once, a call of it that waits is answered
   401 or dropped, its next request is 401, and its tickets stop working. → Task 7
   `a_revoked_or_expired_token_is_refused_at_once`; Task 9 `revoking_cuts_the_stream_and_its_tickets`.
2. **Behind cloudflared every peer is 127.0.0.1:** an attacker's failed logins through the tunnel must not lock the
   person out, and a forged `X-Forwarded-For` from a non-loopback peer changes nothing. → Task 7
   `client_address_trusts_forwarding_only_from_loopback`, `failed_logins_slow_one_address_not_another`.
3. **A limited token and a block that changes workspace:** moved out, its stream gets a `delete` and its calls on it
   are answered as for a block that doesn't exist; moved back, a `put`. → Task 9
   `a_limited_token_hears_only_its_workspaces`; Task 10 `a_limited_token_sees_and_touches_only_its_workspaces`.
4. **The HTTP client goes away while its call waits** (`delegate` with `wait`, `wait_for`): the wait is dropped as an
   agent's closed connection drops it, and the task isn't left "handed" to no one. → Task 7
   `a_call_whose_client_left_is_closed`; Task 10 `a_closed_api_call_drops_its_wait`.
5. **A phone that sleeps with its stream open:** the server's memory for it stays bounded, it wakes to a snapshot,
   not a flood, and with no stream open the UI thread builds no state. → Task 9
   `a_slow_stream_is_resynced_not_grown`; Task 12 `the_tick_runs_only_while_a_stream_is_open`.
